# Existing lifecycle-v1 codec fixtures

These exact UTF-8 bytes were generated by
`starcanonicaljson:canonical-lifecycle-envelope-json`, through the extracted
`star-actor-wire:encode-envelope`. They define no new envelope or schema.
`star.zmq/echo@1` is the existing codec test operation with one required string
field `text`, not a production access operation. Its use does not claim the
`star.access/1` document payload generator is complete.

The shared codec test decodes and byte-roundtrips all six files. Rabbit and
ZMQ carry these same body bytes; Rabbit has additional matching binding-local
message-id/correlation-id/content-type/profile metadata. ZMQ ROUTER identity is
outside the body. Deadline, attempt and idempotency remain inside the lifecycle.

Control meaning:
- accepted is lifecycle admission, not durable commit proof;
- completed is emitted only by the authoritative completion boundary;
- unknown is a nonterminal invocation observation, requiring reconciliation;
- cancel requests arbitration and does not prove the request was cancelled.

A consumer must use its authoritative manifest and shared decoder; JSON shape
alone does not authenticate identity or authorize effects. Legacy SC01/SR01 peers
must fail profile selection explicitly, never receive these bytes as a document.

`exact-document.json` is a real StarIntel 0.10.1 person document with opaque
extensions, validated by the pinned authority reader/schema/semantic validators.
`exact-request.json` and `exact-reply.json` are generated using the real lifecycle
codec. The test-only manifest declares document/scope/precondition maps; it does
not claim to complete the production star.access/1 manifest generator.
Numeric lexemes remain numeric and exact; arrays/null/false/absence stay distinct.
